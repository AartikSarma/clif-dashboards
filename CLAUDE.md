# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose and status

This project serves ICU quality-improvement dashboards for UCSF from the site's CLIF 2.1 database (80K+ ICU admissions). It starts from the collaborator draft at https://github.com/cag-lab/clif-icu-quality-dashboard ("upstream"), which computes respiratory-failure quality measures and writes one self-contained HTML file. That design does not scale to UCSF, so this repo splits it into a batch pipeline and a server that builds report pieces on request.

Status: the repo is scaffolded (git, `uv` project) and the architecture below is a plan. Settled: Python throughout; it runs on the maintainer's laptop for now, with UCSF hosting possible later; aggregation runs on the server, never in the browser. The license is not yet chosen. Commands marked *planned* do not run yet; update this file as each layer lands.

## Upstream, and what to carry over

Clone upstream outside this repo for reference (it is GPL-3.0-or-later; code derived from it inherits that license):

```bash
git clone https://github.com/cag-lab/clif-icu-quality-dashboard <scratch>/upstream
```

What is worth keeping, and where it lives upstream:

- `decisions.yaml` is the single source of every analytic choice (thresholds, windows, modes, eligibility). The pipeline reads values from it by `id`, and the UI renders the same file in each metric's "How this is calculated" panel. Keep this contract: never hard-code a threshold in Python or JS.
- `pipeline/prep.py` builds encounter blocks (clifpy `stitch_encounters`), the clifpy respiratory-support waterfall (hourly scaffold rows flagged `is_scaffold`), IMV runs, and IMV episodes (runs joined when the gap is shorter than `episode_gap_hours`).
- `pipeline/metrics.py` computes one row per IMV episode carrying numerator/denominator columns for every measure (`ltvv_num`/`ltvv_den`, `sat_num`/`sat_den`, ...), plus SOFA, Charlson, and a site-fitted mortality model. Outcomes count only on an encounter's first included episode (`first_in_enc`).
- `pipeline/proning.py` is a Python port of CLIF_Proning_Incidence_Severe_ARF and yields a separate patient-level table.
- `web/src/metrics.js` is the metric registry: each metric's source table (`episodes` or `proning`), aggregation (`ratio`, `mean`, `median`), and data-completeness flags. Aggregation happens in the browser over the episode rows.

Upstream's scaling limits, which this project exists to remove: `clif_io.load_tables` reads every table whole into pandas; `metrics.compute` and `proning.compute` loop over episodes in Python against dict-of-groupby lookups; and `build_dashboard.timelines()` embeds hourly swim-lane series for up to 3000 episodes in the HTML.

## Planned architecture

1. **Batch pipeline** (Python). DuckDB reads the CLIF parquet with column projection, selects the cohort from `hospitalization`/`adt`/`respiratory_support` first, then pulls the large tables (`vitals`, `labs`, `patient_assessments`, `position`) filtered to cohort `hospitalization_id`s. Episode metrics are computed per chunk of encounter blocks, so memory stays bounded and a refresh recomputes only new or changed hospitalizations. Output: episode-level and proning-level parquet tables plus funnel and data-quality summaries.
2. **API server.** Serves filtered aggregates (by month, unit, stratum) over the materialized tables, the paginated patient list, and per-episode timelines built on demand from the raw CLIF tables by `hospitalization_id`.
3. **Web UI.** The upstream React app, with `window.__DASHBOARD_DATA__` replaced by fetch calls.

The episode table is small (tens of thousands of rows at UCSF scale). The server is required for timelines, patient drill-down, and raw-table queries; where aggregation runs is a design choice, not a scale constraint.

## Data

- Synthetic test data: `~/Research/synthetic_clif/synth_clif_10k` (10,000 hospitalizations, 2018-2024, generated by `~/Research/synthetic_clif`). Use it for all development; never point tests at real UCSF data.
- Regression oracle: `tests/oracle/upstream_synth10k.json` holds upstream's output (commit `b3cdf29`, clifpy 2.1.0) on the synthetic data, minus timelines; `tests/oracle/upstream_synth10k_config.yaml` is the config that built it (its `decisions_file` and `output_html` point at a since-deleted scratch clone; repoint them before rerunning). The new pipeline must reproduce the `funnel`, `episodes`, and `proning` rows before any port of metric logic counts as done.
- Upstream baseline on the synthetic data: 3.7 min, 15 GB peak memory, 30 MB HTML, of which timelines are 95% and the 1,295 episode rows 1.5 MB. Memory grows with the size of the raw tables, which is why whole-table loading must go first.
- The synthetic data departs from CLIF permissible values in ways that hide bugs: categories use display case (`IMV`, `Assist Control-Volume Control`, `RASS`, `Full`), so compare categories case-insensitively; there are no `sat_delivery_pass_fail` or `sbt_delivery_pass_fail` assessments and no paralytic infusions, so the documented SAT/SBT and paralytic measures cannot be validated on it; only 12 hospitalizations end in `Expired`, so the mortality model is barely estimable; only 1 encounter meets the PROSEVA ABG criteria, so the proning measures are effectively untestable; and 1,105 of 2,400 ICU episodes drop as outside-hospital intubations, far more than real data would. Report such gaps rather than fabricating inputs.
- CLIF stores datetimes in UTC; days and months are grouped in the site time zone from config.
- Episode rows carry hospitalization IDs and dates, so every built artifact and API response is PHI. Do not commit outputs; the upstream `small_cell_n` rule (n < 11) governs anything shared outside the QI team.

## Commands

```bash
uv sync                      # install dependencies
uv add <package>             # add a dependency (never pip)
```

Build the upstream baseline on synthetic data, from a config file whose `clif_dir` points at the synthetic folder, `demo_mode.reanchor_dates: false`, and `decisions_file` an absolute path into the upstream clone:

```bash
uv run --no-project --with pandas --with pyarrow --with pyyaml --with numpy --with duckdb \
  python -I <upstream>/build_dashboard.py --config <config.yaml> --json-only
```

This is the command that built the oracle (the run reported clifpy 2.1.0). Run it from a directory outside both repos.
